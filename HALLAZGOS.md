## Verificación de la corrección H-04 — 19 de octubre de 2026

- **Aprobación humana:** registrada en esta conversación antes de editar código: «Apruebo ejecutar únicamente H-04 según PLAN.md», aceptando dejar los demás problemas de Clean Code pendientes.
- **Antes:** `npm test -- src/app/login/login.component.spec.ts`: 21/21 pruebas aprobadas sobre el código original. Caracterizan validaciones, preferencias válidas/inválidas, request y timeout, guardado previo a navegación, carga, respuesta sin token, errores y reintento.
- **Después:** expectativas HTML sustituidas por texto y mensaje genérico deliberadamente; agregadas regresiones de caracteres especiales y plantilla. `npm run test:coverage -- src/app/login/login.component.spec.ts src/app/login/login-template.spec.ts`: 24/24 aprobadas.
- **Suite completa final:** `npm run test:coverage`: 25/25 pruebas aprobadas en tres archivos. El componente modificado alcanza 100 % en sentencias, líneas, ramas y funciones, superando el 85 % exigido. La cobertura global de líneas es 39,87 %; no se presenta como cobertura suficiente de toda la aplicación. El reporte está en [coverage/coverage-summary.json](coverage/coverage-summary.json) y [coverage/index.html](coverage/index.html), generados localmente e ignorados por Git. La plantilla se comprueba por separado, no mediante cobertura V8.
- **Compilación:** `npm run build` aprobado; advertencias CommonJS de axios y lodash/merge conservadas, sin ocultarlas.
- **Tipos:** comprobación explícita de los dos archivos de pruebas con el TypeScript instalado (`--noEmit`, resolución bundler, destino y módulo ES2022, decoradores y compatibilidad de imports) aprobada. La primera comprobación detectó un tipo incorrecto en el mock de axios; se sustituyó por `MockInstance<typeof axios.post>` y se repitió satisfactoriamente, sin casts ni dependencias nuevas.
- **Navegador:** frontend local respondió HTTP 200. Se verificaron vista sin mensaje, validaciones, botón deshabilitado durante petición controlada, error 401 con detalle externo inerte y mensaje local sin elementos hijos. Se inyectó texto inerte en el estado de presentación mediante las herramientas de depuración Angular del build de desarrollo y se comprobó que la interpolación conserva literalmente `<b>Literal</b> & "quoted"`, sin crear elementos. - **Flujo en navegador con APIs simuladas:** login correcto, cuerpo con `client`, persistencia de sesión, consulta de tareas con propietario y autorización, tarea visible, exclusión de archivadas y logout con borrado de token/usuario y conservación de preferencias. No se consultaron otros proyectos ni se demostró integración con los backends reales.

La primera espera de navegador agotó su tiempo y la comprobación posterior confirmó el comportamiento con ese evento. La lógica de sincronización de axios y `busy` no se modificó en H-04; no se declara solucionado este problema ni se oculta como un pase automático.

No se modifican servicios, almacenamiento de token, dependencias, estilos ni otros hallazgos; su deuda técnica y los riesgos de logging existentes permanecen pendientes.
